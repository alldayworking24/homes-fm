# FM 규칙 반영 변경 내용 (2026-11, homes-fm)

FM 총괄이 승인한 부담주체 규칙·지점 계약 정보·소분류 변경을 homes-fm 화면에 반영한 내용입니다.
**추천값은 참고용이며, 부담주체는 담당자가 직접 선택합니다(자동 입력 없음).** 고객·투자사 안내 전에는 계약서·특약 확인과 담당자·조직장 승인이 필요합니다.

## 어느 코드가 실제로 쓰이나
- 실제 동작 코드는 `index.html` 안의 **인라인 `<script>` 3개 블록**입니다. 루트의 `script.js`, `script_inline_0.js`, `script_inline_1.js`, `script_last.js` 는 index.html 이 로드하지 않는 **오래된 사본**이라(README v50 참고) 수정하지 않았습니다. `archive/` 도 그대로입니다.
- 새 코드는 별도 파일로 추가했습니다.

## 추가·변경 파일
| 파일 | 내용 |
|---|---|
| `fm-rules.js` (신규) | 공용 규칙표(`window.FM_RULES`): 규칙·지점 계약 정보·추천 함수·패널. 관리자 앱과 같은 파일 |
| `fm-rules-ui.js` (신규) | homes-fm 화면 연결. 기존 함수(`openRepairDetail`, `saveRepair`, `updateRec`, `setBranch` 등)를 감싸는 방식 |
| `index.html` (수정 3곳) | `fm-rules.js` 로드, `fm-rules-ui.js` 로드(앱 스크립트 뒤), 룸체크 재저장 시 필드 보존 호출 1줄 |
| `docs/migrations/2026-11-fm-taxonomy.sql` (신규) | fm_taxonomy 변경 SQL(DB 관리자 검토용, 미실행) |

## 화면 변경
1. **보수 상세(보수 수정) 화면 — 항목마다 「부담주체 추천 · 청구」 블록**
   - 분류(대›중›소) 선택 → 지점·분류·원인 기준 추천(부담주체, 규칙 상태 확정/잠정/보류, 처리 등급, 필요 증빙) 표시. 항목명으로 분류를 추정해 미리 선택해 두며 바꿀 수 있습니다. 규칙이 없으면 「규칙 없음 — 담당자 판단」.
   - 입력칸: 원인(패널 안 선택), 부담주체, 청구 상태, 금액, 메모.
   - 기존 「비용 부담 주체」(`costBearer`)는 그대로 동작하며 덮어쓰지 않습니다. 두 값이 어긋나면 안내 문구만 표시합니다.
   - 보기 전용·잠금 상태(보수 완료 잠금 등)에서는 입력칸이 비활성화됩니다.
2. **지점 운영 정보 카드** (점검 위치의 지점 선택 아래, 기본 접힘)
   - 모든 사용자: 구조 · FM 업체 · 부담 원칙 요약.
   - 로그인 계정의 `app_users.role` 이 `admin` 또는 `manager` 일 때만: 건물주/투자사, 계약 시작·만기(D-day)·해지 통보·갱신, 메모. 전화번호는 데이터에 없습니다.

## 새 항목 필드 (payload, DB 스키마 변경 없음 — 관리자 앱과 동일한 이름)
`burdenCause`(원인), `claimStatus`(청구 상태), `claimAmount`(숫자), `burdenMemo`, `burdenConfirmedBy`, `burdenConfirmedAt`(ISO).
- homes-fm 에서만 추가로 `burdenCategory`(선택한 분류 경로, 예: `설비›급배수›샤워기`)를 저장합니다. 관리자 앱은 무시해도 됩니다.
- 아무것도 입력하지 않으면 필드를 만들지 않습니다. 부담주체를 선택·변경해 저장했을 때만 `burdenConfirmedBy/At` 이 기록됩니다(「규칙 확정」이 아니라 「담당자 입력 기록」).
- 부담주체 선택값: 홈즈, 투자사, 세입자, 갑(임대인), 을(홈즈)/전차인, 협의 필요. 청구 상태: 해당 없음, 선지출, 청구 준비, 청구중, 회수, 미회수.
- 룸체크를 수정 저장해도 이 필드들이 유지되도록 `FM_RULES_UI.carry()` 를 추가했습니다.

## 분류(소분류) 변경
- **homes-fm 에는 fm_taxonomy 를 읽는 코드가 없습니다.** 분류 체계는 관리자 앱 전용이므로 homes-fm 에서는 `fm-rules-ui.js` 의 `TAXONOMY` 표(부담주체 추천 조회용)에만 반영했습니다. 신설 소분류 14개 추가, 위생·해충›욕실은 곰팡이·배수구 악취·실리콘 오염만, 변기·세면대·샤워기는 설비›급배수로 이동.
- 점검표 항목(예: 욕실/화장실›변기)은 별도의 체크리스트 양식이라 바꾸지 않았습니다.
- `index.html` 의 `REPAIR_TYPE_RULES`(엑셀 5대 유형 키워드 분류)는 관리자 앱 `categoryRules` 와 같아야 하므로 **이번에 바꾸지 않았습니다**. 관리자 앱 쪽 변경과 함께 맞추세요.
- DB 반영은 `docs/migrations/2026-11-fm-taxonomy.sql` 을 DB 관리자가 검토 후 실행합니다(이 작업에서는 실행하지 않음).

## 규칙 유지 방법
- 규칙표는 DB 없이 **정적 파일 `fm-rules.js`** 입니다. 규칙 수정은 이 파일을 갱신하고 배포하며, 관리자 앱과 같은 파일을 쓰도록 맞추세요.
- DB 기반 규칙(burden_rules 테이블 등)은 **구현하지 않았습니다**.
- 「잠정」·「보류」 규칙(예: 남영 상세표 누락 3건, 원효로240)은 계약 원문 확인과 FM 총괄 확정이 필요합니다. 화면에는 잠정/보류로 구분 표시됩니다.

## 알려진 한계
- 보수 등록(룸체크 입력) 화면에는 넣지 않았고 **보수 상세(처리) 화면에만** 넣었습니다.
- 분류는 항목명 키워드로 추정만 하며 정확하지 않을 수 있습니다. 추천 패널의 근거·메모 문구에는 계약 관련 설명이 포함될 수 있어, 권한별로 숨기지는 않았습니다(원문은 `fm-rules.js`).
- 루트의 오래된 `script*.js` 사본은 갱신하지 않았습니다.
- 지점 카드는 선택된 지점명이 규칙표의 지점명(남영·선정릉·안암·아코모가산·아코모회기·원효로240)과 일치할 때만 정보가 나옵니다.

## 테스트 메모
- 가짜 DOM 하네스(Edge headless)로 확인: 패널 마운트, 분류 추정, 입력→저장(`updateRec` 경유) 후 필드 기록, 재열기 복원, 잠금 시 비활성, `carry`, 일반/관리자 권한별 지점 카드, 신설 14개 소분류의 추천 호출 예외 없음.
- 전체 `index.html` 을 열어 오류 없이 로드되고 훅이 설치되는지 확인.
- **확인하지 못한 것**: 실제 로그인, Supabase 저장·다른 앱과의 연동, 실제 데이터, 모바일 실기기 화면.

## 수정: 부담주체 칸 통합 (2026-11)
- 새 「부담주체」 칸을 없애고 앱의 기존 「비용 부담 주체」(costBearer: 투자사(임대인) / 당사(홈즈) / 세입자 / 기타 / 미정 / 보수 불필요) 하나만 사용합니다. urdenPayer 필드는 더 이상 만들지 않습니다.
- 추천 패널에 「추천값 적용」 버튼이 생겼습니다. 누르면 기존 비용 부담 주체 칸(과 청구 상태·메모)이 채워지고, 저장은 기존 저장 버튼으로 합니다. 자동 입력은 없습니다.
- 청구 상태 칸은 비용 부담 주체가 투자사(임대인)·당사(홈즈)일 때(또는 이미 값이 있을 때)만 보입니다.
- 규칙 → 선택지: 홈즈‡(선정릉) = 투자사(임대인) + 청구 상태 선지출 / 투자사†·투자사*·갑 = 투자사(임대인) / 을(홈즈)/전차인(남영) = 당사(홈즈) + 메모 「전차인 청구 대상」 / 세입자 = 세입자 / 보류·확인 필요 = 미정. 수선과 교체가 다른 규칙은 추천하지 않고 직접 선택하게 합니다.

## 추가: 점검 목록에 첨부(사진) 표시
- 점검 목록의 각 기록 줄에 사진·첨부가 있으면 파란 칩 「첨부 사진 N장」이 표시됩니다(index.html의 enderList, ttachedPhotoCount). N은 항목별 점검 사진(photos), 보수 전 사진(eforeRepairPhotos), 보수 후 사진(fterPhotos) 장수의 합계이며, 사진이 없으면 칩을 표시하지 않습니다.
- 사진 외 다른 형식의 첨부 파일은 homes-fm 기록에 저장되지 않아 집계하지 않습니다(코드 기준, 실제 데이터로는 확인하지 못했습니다).

## 수정: 점검 위치 레이아웃
- 「지점 운영 정보」 카드가 지점·층·호실 선택 격자 안에 들어가 칸 하나를 차지하는 바람에 호실이 아래로 밀리던 문제를 고쳤습니다. 카드는 이제 격자 바깥, 선택칸 바로 아래 전체 폭으로 표시되고 지점·층·호실 배치는 원래대로입니다(m-rules-ui.js의 ensureCard).

## 추가: 더보기 화면 개편
- 「더보기」를 내 계정 카드(이름·권한 배지) → 현황 요약(전체 기록 합계, 상태 비율 막대, 보수 예정·보수중·보수완료 수치) → 영역별 메뉴(조회·도움말·데이터 관리) 순서로 다시 구성했습니다(more-menu.js 신규, index.html에 로드 1줄). 기능(계정 관리, 지점·호실별 수리 이력, 사용법 보기, 데이터 백업)은 그대로입니다.
- 보수 예정·보수중·보수완료 수치를 누르면 목록 화면이 해당 상태 필터로 열립니다. 기존 더보기 마크업은 숨기기만 하고 그대로 두었으며 기존 enderMore()가 계속 값을 채웁니다.
- 막대의 네 구간은 보수완료·보수중·보수 예정·룸체크 완료이며 합계가 전체 기록과 같습니다.
